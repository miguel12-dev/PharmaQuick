
1. Arquitectura y Definición Técnica
Estrategia Multi-Tenant (Database Clustering)
Para balancear el aislamiento de datos y la eficiencia de recursos, implementaremos un Middleware de Conexión Dinámica:
Mecanismo: El sistema contará con una base de datos central (pharma_master) que mapea cada farmacia_id a un clúster específico.
Conexión: Al iniciar sesión, el servicio de autenticación identifica el clúster (ej. db_cluster_1 para las farmacias 1 a 5). Se utiliza un PDO Factory que instancia la conexión basándose en el prefijo de la base de datos del clúster, permitiendo que 5 farmacias compartan recursos de servidor pero mantengan independencia lógica.
Flujo de Inventario (Kardex-Driven)
La integridad no reside en la aplicación, sino en la base de datos mediante el Trigger Centralizado:
Single Source of Truth: Ningún proceso (Venta, Reserva o Ajuste) modifica la tabla lotes directamente. Todos deben insertar un registro en movimientos_inventario.
Garantía de Integridad: El trigger trg_kardex_stock asegura que la suma de movimientos siempre coincida con el stock actual, evitando inconsistencias por cierres inesperados del navegador o fallos de red.
Stack Técnico
PHP 8.x Nativo: Elegido por su bajísimo overhead y facilidad de despliegue en servidores locales (XAMPP/Docker) en zonas de baja conectividad.
Librerías Composer:
phpoffice/phpspreadsheet: Gestión robusta de lectura de plantillas de inventario y exportación de reportes.
dompdf/dompdf: Generación de facturas y reportes de farmacovigilancia en PDF desde plantillas HTML/CSS.
